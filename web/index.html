Drive it from an agent

      
AIPLAY Studio speaks MCP, so an assistant can use it the way you
        do — write a song, draw pictures, render clips, read a track’s beat grid,
        restyle a video, and lay the result out on the timeline. It is the same HTTP API the
        app itself runs on, with a typed face on it, so there is one implementation of each
        behaviour and the two cannot drift apart.


      
Point something at it

      
Studio must already be running — the MCP server is a thin client,
        not a second copy of the engine. Add this to your assistant’s MCP configuration:

      
loading…

      
Set AIPLAY_URL if Studio is not on its default port.
        Everything runs on your machine; nothing is sent anywhere.

A worked example

      
What “make me a music video” actually looks like as a sequence:

      
    
        
  1. make_song with a structured caption, then wait_for_song
          — four to five minutes for a three-minute track.
    2. 
        
  2. make_image a few times for the look you want, then
          make_clip with each one as first_frame, so the clips match
          the art rather than being unrelated.
    3. 
        
  3. get_beats to see the tempo. Check it against what you would tap
          — tempo detection has to choose between a beat and its octave, and on
          half-time material it usually picks the fast one.
    4. 
        
  4. restyle_clip if you want the audio-reactive look: it keeps the
          motion and drives how hard it restyles from the song’s bass.
    5. 
        
  5. build_music_video to lay the clips on the bar lines and set the
          effects. It writes a project; you open it and press Export.
    6. 
      


      
What it cannot do, and why

      

        
Export a video file

        
Studio’s export is a real-time capture of a canvas by the browser, so there
          is no server-side renderer to call. build_music_video writes a
          project and a person opens it and presses Export. A tool that appeared to
          render and handed back something that was not a video would be worse than the
          honest gap.


        
Restyle more than five seconds in one call

        
One LTX run is 121 frames — that is a property of the model, not a setting.
          Longer videos are several runs chained, each seeded from the last frame the previous
          one produced so the seam does not reset.


        
Render two things at once

        
Covers, images, clips and restyles share one queue, and music always preempts it.
          A tool that waits will wait for the song in front of it too. That is the machine
          being honest about having one graphics card.

      


      
The server is server/mcp.js — about four hundred lines,
        no SDK. MCP over stdio is newline-delimited JSON-RPC, and taking on a dependency tree
        to avoid writing forty lines of it would have cost more than it saved.

    


    
    

      
Reactive

      
Pictures that change on the beat. The song is analysed, its
        peaks are found, and the reference images are cross-faded against each other
        in time with them — so the picture arrives on the hit rather than on a
        timer.


      
      

        
This needs a second engine

        
The nodes that do this are GPL-3.0. AIPLAY Studio is Apache-2.0,
          so they cannot ship inside it — the same reason ComfyUI itself is a
          separate program Studio talks to rather than something bundled. Run a
          second ComfyUI with these installed and Studio will find it.

        

        

        
Studio never downloads or installs any of this for you, and
          the licences are between you and their authors.

Why “MiniMax-Music3” is on the screen

      
The music engine’s Community Licence asks for its name to be
        displayed by anything built on it. That is a condition of use rather than a
        courtesy, so it stays on the main window instead of moving here — a
        credits page is exactly the “About box” the requirement exists
        to avoid. The line in the bottom-left corner is that attribution.


      
The software

      

        
ComfyUI GPL-3.0

        
Does all the real work. A separate program that Studio starts and
          then talks to over its HTTP API — not linked, not bundled, not
          modified. Studio’s own licence is unaffected by that boundary, and
          the boundary is deliberate.


        
vendor/minimaxmusic Apache-2.0

        
MiniMax Music 3 model definitions, from The MiniMax Team and The
          HuggingFace Team. Used to run the DAV audio encoder outside ComfyUI
          — the one step ComfyUI refuses — which is what makes starting
          a render from real audio possible. Modified: the diffusers base
          classes were stripped, because they exist only to support
          from_pretrained() and installing diffusers broke the
          engine’s torch build. The model code itself is unchanged.


        
ComfyUI_Yvann-Nodes GPL-3.0

        
Audio-reactive scheduling for ComfyUI, by Yvann Barbot and Lilia.
          Not bundled and not linked — the same boundary that applies to
          ComfyUI itself. Studio’s own audio layer was written from scratch,
          because a GPL pack cannot ship inside an Apache-2.0 app. But the design
          came from reading theirs: placing image guides on the beat rather than on
          a fixed stride is their peaks_index idea, and their graph is
          the reason the guide strengths in server/workflow.js are shaped
          the way they are. Reading their work saved us a great deal of guessing, and
          measuring against it showed us what our own stack could not do.


        
ws MIT

        
The only runtime dependency Studio installs. One npm package, on
          purpose.

Cover art

        
Every finished song gets a cover automatically. The prompt is
          built from two halves: the style line below, then
          , evoking <subject> — where the subject comes from the
          song's caption (musical notation stripped out), or its title, or a rotating
          pool of neutral objects for untitled tracks. Edit the style to restyle the
          whole library's future covers; the per-song subject stays automatic.
