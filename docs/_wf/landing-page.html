AIPLAY Studio.

A desktop studio for MiniMax Music 3 and the four things that go around a track. One long-lived ComfyUI process. No model weights in the box.

  • node + static UI
  • one runtime dependency: ws
  • graphs exported as ComfyUI JSON
  • measured on one machine
01

What it is

AIPLAY Studio is a Node server and a static HTML/CSS/JS interface that drives a single long-lived ComfyUI process: you write a song, and the same session gives you its cover, its stems, its timed lyrics and a video. It ships no model weights. The Models screen lists every capability with its real byte count and its licence and fetches on request, so what you download is a decision you make with the size in front of you. The four graphs behind the buttons are exported to workflows/ as ComfyUI-loadable JSON — nothing here is a pipeline you cannot open in the editor you already have. The only runtime dependency is ws. Licence Apache-2.0.

Measured on

NVIDIA GeForce RTX 4070 Ti SUPER, 16 GB VRAM · 32 GB system RAM · Windows 11 · torch 2.13.0+cu130 · ComfyUI 0.33.0. Every number on this page came off that one machine, in that one configuration. It is not a benchmark suite and it is not a promise about yours.

03

Install

  1. Clone and install

    One dependency comes down. Nothing else is fetched at this point — no weights, no models.

    git clone https://github.com/Senzube4n/AIPLAY-Studio
cd AIPLAY-Studio
npm install

  2. Point it at ComfyUI and start the server

    The server talks to one ComfyUI instance over its websocket API and keeps it warm. If yours is not at the default host and port, set that first; then open the UI in a browser.

    node server/index.js
# http://localhost:4173

  3. Open Models and fetch what you actually need

    Each capability is listed with its real size on disk and its licence. Music alone is 11.9 GB; both video engines together are another 74.2 GB. Read the licence column before you take the video weights — two of them restrict where and how you may use the output.

Unproven

The 6 GB music tier has not been run on real 6 GB hardware. It is a stated minimum, not a measured one. The 12 GB recommendation is what the measurements above were taken against.

Quantization: there is no quality ladder

int8 is the default, and the reason is that the alternative does not buy anything measurable. Against a converged reference, int8 and fp16 both land at 4.2 dB SNR and +10.8 dB NMR — the same number, twice. Pairwise SI-SDR across int8, fp16 and fp32 reads 35.34 / 32.38 / 35.46 dB, which is not a ladder: fp32 is not a reference the other two converge on. Paying 4× the memory for fp32 does not buy you a better master here.

Two practical notes

instrumentals
An empty lyric box gives you 32.5 s of audio. Eight bare section tags — no words, just structure — give you 157.2 s. If you want a long instrumental, the model needs a form to fill, not silence to fill.
lyric timing
On a real track, 97.9% of words were timed by direct match. Line timing is reliable. Word timing on sung vocals is approximate — good enough to drive a karaoke line, not good enough to trust frame-exact.
05

Audio reference, and what it can honestly do

This is the most interesting thing in the repository, and it is also the one most easily oversold, so here it is with its limits attached.

The wall

ComfyUI ships the MiniMax DAV decoder only. Ask it to take audio in and it raises MiniMax Music3 DAV cannot encode audio. That is a real wall, not a missing flag: there is no encode path in the node.

Why it works anyway

The encoder weights exist separately from what ComfyUI ships. The load-bearing detail is that in that separate checkpoint, the 121 decoder tensors are bit-identical to ComfyUI’s own. Same decoder, byte for byte — which means a latent encoded out of process is a latent this sampler already understands. Nothing is being coerced or approximated at the boundary. You encode elsewhere, load the latent through stock nodes, and the graph does not know the difference.

What it is not

It steers the render, not the composition. You get that song’s shape with a new sound — not that song’s tune with new words. If what you wanted was a cover, this is not that, and no setting on the dial turns it into that.

Closed, with a reason

Extending an uploaded track is not possible here. Extension needs the autoregressive trajectory, and recovering one from audio needs an RVQ tokenizer that has never been released. This is not a to-do item; it is a missing component nobody outside the original lab has.

Where LTX’s speed comes from

It is the schedule, not a faster model. Eight steps at half resolution, a latent ×2 upscale, then only three steps at full size. Most of the sampling happens where pixels are cheap. Worth knowing, because it means the advantage is a technique with a shape you can reason about, not a black box that is simply better.

LTX 2.5 also looks better by eye on the clips tested. That is a judgement, not a measurement, and it is one person’s eye.

Seamless loop

Use the same picture as both first and last frame. Measured on that setup, the clip still animates through the middle — mid-clip divergence 6.00 — while returning home at the end, divergence 1.62. You get motion and you get a loop; you do not have to trade one for the other.
