## 1. The visualizer — why it looks like it only used the first frame

This is the blocker. Nothing about the open-source relaunch should ship until it
is fixed, per the owner.

### What the code actually does

The source frame **does** advance — `scripts/reactive_video.mjs:459` passes
`src: ${SRC_DIR}/${frames[i]}`, a different file every iteration. So the literal
hypothesis ("it only takes the first frame") is not what happens.

The real mechanism is worse, because it is a design parameter rather than a bug:

```js
const SRC_WEIGHT = Number(opt("source", 0.34));            // line 73
g[33] = ImageBlend({ image1: zoomed_previous_OUTPUT,
                     image2: current_source_frame,
                     blend_factor: SRC_WEIGHT })            // line 315
```

Every frame's starting picture is **66% accumulated feedback, 34% the actual
video**. Then `denoise` 0.42–0.58 reworks what survives. Three things compound:

1. **Frame 0 is the most heavily stylised frame in the run.** It has no feedback
   to blend with, and `steps_N = S_MIN + 1 = 7` ⇒ `denoise = 7/12 = 0.583`
   (line 442). It is the strongest single transformation anywhere in the chain.
2. **Frame 0's output becomes the frozen `anchor`** (line 466) and is
   `ColorTransfer`-ed onto **every** subsequent frame at `COLOUR * 0.6 = 0.33`
   (line 334). That is Deforum's "Match Frame 0" and it is deliberate — but it
   re-imposes frame 0's palette forever.
3. At 34% injection against an accumulating loop, the video's own content is
   overwritten faster than it is re-supplied.

Net: after roughly 20–40 frames the picture is a self-referential drift seeded by
frame 0, wearing frame 0's colours. **It looks exactly like "it only used the
first frame", and functionally it nearly did.**

### Fixes, in the order worth trying

1. **`--source 0.65`** (from 0.34). The single highest-value dial — the video
   reasserts itself every frame instead of being outvoted.
2. **`--denoise-min 0.30`** (from 0.42). The file's own comment says effective
   strength accumulates inside a feedback chain, so the usable per-frame band
   sits lower than a single pass suggests. It was never re-tuned after the chain
   was built.
3. **`--colour 0.25`** (from 0.55), or re-anchor every N bars instead of freezing
   frame 0 forever.
4. ⚠ **Measure with two seeds before believing any difference.** The
   `shift_video 4.0` result was withdrawn for exactly this reason — a re-sweep
   put every metric inside the seed-to-seed noise floor.

## 1a. MEASURED 2026-08-20 — the fix list above is wrong

Ran the A/B the section asks for: 0.34 vs 0.65, FOUR seeds, 61 frames. Findings,
in the order they change what to do.

**`--source` is not the fix. The style reference is.** The first A/B was run
without `--style-ref` and every arm collapsed into flat-lay still-life by frame
18 — not the dancer, and not frame 0 either. That run was invalid; its metrics
were scoring dancer-against-still-life. `reactive_video.mjs:136` already says
so: *"six variants of prompt, denoise band, **source weight** and colour
anchoring all converged to graphic collage"*, and the script prints a warning
at startup when no reference is given. Source weight had already been swept.

**The seed was hardcoded at 77000** (`:463`) with no CLI dial, so every previous
observation of this renderer came from one seed — and it is a bad one. At 77000
the figure collapses at BOTH source weights; at 12345 it survives at both. Rule
#4 above ("two seeds before believing a difference") was literally impossible to
follow. `--seed` now exists, defaults unchanged, and prints in the run header.

**With a reference, `--source 0.65` does hold up**, and the default is now 0.65:

FOUR seeds, paired by seed (the correct design - each seed runs at BOTH
settings, so the statistic is the WITHIN-seed delta):

| metric (tail half)             | mean paired delta | seeds agreeing | t (3df) |
|--------------------------------|-------------------|----------------|---------|
| resemblance to frame 0 (down)  | -0.137            | 4/4            | -3.28   |
| follows-the-video diff (up)    | +0.305            | 4/4            | +4.02   |

Both clear p<.05. At 0.34, two of four seeds tracked the video at zero or
NEGATIVE lead (90210: -0.154) - the output resembling the video's FIRST frame
more than the current one, which is the reported bug in a number. At 0.65 all
four are positive.

WARNING "tracks the source" is TAUTOLOGICAL - the dial blends more source in, so
corr(out_i, src_i) rises by construction. The differential
`corr(out_i,src_i) - corr(out_i,src_0)` cancels it; that is the row above.
WARNING Analyse PAIRED. The first pass pooled the arms and compared means
against the seed spread, discarding the pairing and calling a 4/4-consistent
effect "inside noise". n=4 is still thin - t=-3.28 only just clears 3.18.

**So items 2 and 3 above (denoise-min, colour) are untested** and should not be
applied on the strength of this section.

### The structural alternative, which may be the real answer

`restyleGraph()` in `server/workflow.js:443` already does what the Deforum chain
struggles to: it reads the video **inside ComfyUI** via
`LoadVideo → GetVideoComponents → ImageFromBatch` with `batch_index: i`, and
places each guide at `frame_idx: i` (lines 489–501). **Per-frame timeline
alignment is correct by construction**, and it keeps the real scene.

Measured guide density — do not relearn this:

| guide every | strength | result |
|---|---|---|
| 8 | 0.70 | zero restyle — reproduces the source |
| **16** | **0.30** | **the look** |
| below ~0.25 | — | loses the choreography |

Also measured: `SplitSigmasDenoise` **quantises denoise to 1/steps**
(`total_steps = round(steps * denoise)`) — it is not a continuous dial. Drive the
integer step count and back-solve denoise.

### Three video paths exist; only one is wired

| path | character | wired? |
|---|---|---|
| Deforum chain (`scripts/reactive_video.mjs`) | wanders, has character | **script only** |
| LTX restyle (`restyleGraph`) | keeps the real scene | ✅ `/api/restyle` + MCP `restyle_clip` |
| LTX morph (`morphGraph`) | abstract — the usual Yvann shape | **script only** (`scripts/morph_test.mjs`) |

## 4. Gotchas that cost time before

- **The grid lists the directory, not the manifest** — a clip that threw still
  appears, so failures are invisible. This hid a `prompt is not defined`
  ReferenceError present since the first public commit.
- **Config one level too deep has now bitten 4×.** `video.when` / `.seconds` /
  `.width` / `.height` live on the **engine**, not on `config.video`. A default
  path no UI exercises has never run.
- **Routing is an explicit table in `routes.ts`, not a filesystem scan** (AIPLAY
  side) — copying an endpoint alone still 404s.
- **Cloudflare answers a urllib User-Agent with 403** — deploy checks lie.
- **H3 ran without its turbo LoRA** for a long time (`turboLora` named, never
  loaded). The A/B is night-and-day. Any sweep from before that fix is invalid.
- **Re-tagging restamps mtime** — it scrambled 11 timestamps once.

  pulled from the public page. Do not restore it.
