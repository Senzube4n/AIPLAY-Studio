## 2. What shipped this session

### Audio-reactive, ours, Apache-2.0 (the Yvann answer)
Yvann's pack is GPL and architecturally dead here, so the *capability* was rebuilt
from scratch. Same three jobs its nodes do — analyse, find peaks, drive the visuals
— with no GPL anywhere near it.

- **`scripts/beats.py`** now also emits **per-band envelopes** (`bass` 20–160 Hz,
  `low` 160–800, `mid` 800–3k, `high` 3k–11k) and the onset envelope, both at a
  fixed **30 fps**, from the STFT it already computed. Bands are in **hertz**, not
  bin fractions — bin fractions depend on sample rate and FFT size, so the browser
  and the offline path disagreed about what "bass" meant.
  Each band is normalised to its **own 97th percentile**, so a mix where the hats
  sit 30 dB under the kick still has a usable hat envelope.
- **`GET /api/beats/<file>`** — beat grid + envelopes, cached **on disk** at
  `output/.beats/<name>.json`, guarded by the source mtime.
  Measured: **3.15 s cold, 41 ms cached**; 142 KB for a 2:49 track.
- **Studio** draws beat and bar lines on the ruler, **snaps to them**, and has
  **"Cut to beat"** — every clip on a track onto a bar line, N bars each.
  Verified in the browser: 3 clips landed on 0 / 3.135 / 6.246 s against bars at
  exactly those times.
- **Effects are driven by the measured grid** (`beatSync`), not only by the live
  analyser. This is the part that matters: the live analyser needs the tab visible
  and playing, so an export in a background tab reacted to *nothing*. The offline
  path depends only on `t`, so a scrub to the same frame gives the same picture.
- **Half / double time.** Tempo detection must choose between a beat and its
  octave. This app's own "cloud rap, 72 BPM" render measures **154** (= 77 × 2).
  Both readings are defensible; only a listener can pick, so the UI asks.

### Thanks page (task #43, done)
A view in `.stage`, and **the NOTICE file rendered**. The model table is built from
the **live `/api/models` catalogue**, not typed out — a hand-written licence table
is correct the day it is written and wrong from the next model onwards. The H3
territorial warning surfaces automatically from `cap.region`.

### Upscale + frame interpolation, Images page, per-clip FX, projects, three-dock
layout — as described in the previous handover; all still stand.

## 3. Bugs found and fixed

### 🔴 Every finished video clip threw, since the first public commit
`art.js` emitted the `clip` completion event with a **bare `prompt` identifier that
has no binding in that scope** — the resolved prompt is a local inside `#clip`.
`ReferenceError: prompt is not defined`, thrown **after** the render finished and
the file had been moved into the clip folder.

Invisible because **the Video grid lists the directory**, so the clip appeared and
looked fine. Everything the event was supposed to do was skipped: the clip was
never written into its song's sidecar, never recorded a render time or a prompt,
and an Overnight video row sat at "waiting" forever with the finished clip on disk.

Evidence: of 53 tracks, the only 3 with an attached clip were made on **Aug 17** —
*before* the first commit (Aug 18) introduced the metadata block. `#clip` now
records `job.usedPrompt`.

### 🔴 A thrown art job never resolved its Overnight row
Every stage is ticked off from its **success** event. A job that threw emitted
none, so the row said "waiting" with nothing left that could change it —
indistinguishable from queued. The runner now emits `failed`, and `index.js` marks
the stage (and, for video, the enhancement that can no longer arrive).

### 🔴 Almost nothing in Settings survived a restart
`settings.json` held the folders, the API mode and the custom-workflow assignments
— **and nothing else**. Video on/off, engine, when, stems, lyrics, output format,
cover art, enhancement and the VRAM tier were all **in-memory only**. The symptom
is a switch that "will not stay on", and it is invisible from inside one session.

This is the actual cause of the greyed-out video stage: the models were all present
the whole time. `config.js` now carries `PREF_PATHS` — an **allow-list with a
validator per field**, because config also holds measured constants (sigma
schedules, the fp32-VAE rule) that a stale file must never reach.

### 🔴 `video.when` was declared one object too deep
It lived inside `engines.h3`, where nothing reads it, so `config.video.when` was
`undefined`, every `want("video", config.video.when)` compared `undefined === "all"`,
and `maybePost` never fired. The field had been added *specifically* to make "a clip
for everything I star" reachable — and it still was not. It looked fine because the
route ASSIGNS it, so it springs into existence the first time the dropdown changes.

### 🔴 The run's chain did not win for video
`index.js` gated the request on `config.video.enabled` as well as the chain, so a
run could tick "video", the panel would list the stage, and nothing would queue it.
The chain now wins, exactly as it does for cover/stems/lyrics; what genuinely stops
it is **missing weights**, and that is what is checked (`videoReady()`).

### 🔴 Adding media to the timeline was neither undoable nor autosaved
`autosave()` is reached **only** through `pushUndo()`, and neither drag-and-drop nor
click-to-add called it. Assembling a timeline by dragging — how the editor is meant
to be used — survived nothing. Measured: dropped a song, waited out the 800 ms
debounce, reloaded, audio track came back empty. `pushUndo()` now lives inside
`addClipTo`/`addSongTo` so no call site can opt out.

### 🔴 Late metadata silently undid an edit
`attach()` sets `it.dur` from the media element after an await that takes seconds.
Anything that changed the clip's length while waiting was reverted. Measured:
"Cut to beat" set a clip to 3.111 s and it snapped back to 5 s while its **start**
stayed on the bar — which reads as a broken feature, not a race. `keepTiming`
covers what the caller knows; this covers what nobody knows at call time.

### 🔴 The beat grid queued behind audio decoding
`loadBeats` ran after `await attach(...)`, so the ruler had no beat lines until a
three-minute FLAC reported its duration. Started before the attach now, and not
awaited — the `.then` repaints when it lands.

### 🔴 One slider drag destroyed the undo history
Per-clip FX called `pushUndo()` on every `input` event. Dragging Amount across its
span pushed ~100 snapshots into a stack capped at 50. Now one entry per **gesture**,
closed by `change`/`blur`.

### Smaller
- The `lrc` row was **never listed for any song** — `expectedStages` read
  `job.lyrics` from a jobs *snapshot*, which carries no lyric text. The whisper
  pass ran; it just had nowhere to report. `hasLyrics` now travels on the snapshot.
- `clipSeconds` meant **render time** in the sidecar and **clip duration** in the
  meta store — one key, two meanings, written on the same line. The sidecar field
  is now `clipRenderSeconds` (old spelling still read).
- `/api/image/<name>` hardcoded `image/png` while accepting jpg/webp — the same
  mistake `/api/clip/` had.
- A song whose duration cannot be read no longer becomes **5 seconds**; the
  library's known length is used.
- Autosave was writing **fewer fields than `projDoc()`** — recovering from a lost
  tab quietly reset the beat settings and visualiser size to defaults.

## 4. Gotchas worth keeping

- 🔴 **Chrome suspends background tabs harder than you think.** `requestAnimationFrame`
  stops *and* **media elements never load** — `readyState 0`, `duration NaN`, **no
  error**, forever. Both audio and video. A black canvas or a 5-second song seen
  through claude-in-chrome is almost always this. **Check `document.visibilityState`
  before debugging any of it.** This has now cost two sessions.
- ⚠ **`paintTimeline()` rebuilds `#stLanes.innerHTML`.** A held lane reference is
  detached, and a synthetic drop dispatched on it never reaches the delegated
  listener. Re-query before every drop when scripting the UI.
- ⚠ **New views go in `.stage` as `<div id hidden>`.** `.shell` is a grid; a
  `<section>` added as its child becomes a fourth column ~100 px wide painted over
  the navigation.
- **No typechecker and no linter.** `tsc` is not installed. `node --check` catches
  syntax only — it would never have found the `prompt` ReferenceError. The honest
  substitutes are `scripts/trace_load.mjs`, `scripts/test_timeline.mjs`, and
  actually exercising a path end-to-end.
- Edits are applied as **idempotent Python patchers** in the scratchpad. Anchor on
  text with no backslashes or backticks, or the escaping through nested heredocs
  will silently no-op.
- `/api/models` returns **`capabilities`**, not `models`.
- ComfyUI COMBO options are at `input.required.<name>[1].options`, not `[0]`.
- `SaveVideo` reports its output under **`images`** with `animated: true`.
- The art queue is **idle-drain**: music always preempts.
- 🔴 Give the frames back after an upscale (`POST /free {"free_memory":true}`) or
  one enhancement costs the machine ~15 GB for the session. Never `unload_models` —
  that evicts the music engine.
